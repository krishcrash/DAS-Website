# Dead Auteur Society

Static site for [deadauteursociety.com](https://deadauteursociety.com), built with
[Hugo](https://gohugo.io) (extended, v0.166+) and a Python data pipeline, deployed to GitHub Pages.

## Layout

```
master-data/                 ← the source of truth you edit
  ratings_by_metric.csv        every score, one row per user × film × category
  config_users.csv             member codes, names, active flag
  max_ratings.csv              max score per category
  wordpress/*.xml              one-off WordPress export (migration input only)
scripts/                     ← Python pipeline
  migrate_wordpress.py         one-off WordPress → Markdown migration
  build_data.py                scores + unified dataset (every build)
  build_charts.py              analytics charts (every build)
  hash_password.py             hash the club password for the submit page
  legacy/website_analysis.py   the original chart script, for reference
  requirements.txt
content/                     ← Markdown pages
  reviews/<slug>.md            one file per film — editorial front matter + synopsis
  analytics/                   /analytics/ and /analytics/details/
  submit.md                    /submit.html (password-gated score submission)
layouts/                     ← Hugo templates
  _default/baseof.html         base shell: atmosphere, masthead, footer
  partials/frame.html          aspect-ratio-safe image frame (any poster shape)
assets/                      ← processed by Hugo (bundled, minified, resized)
  css/  js/
  images/posters|banners|reviewers/
build/                       ← generated by the pipeline, git-ignored
  data/   → mounted as Hugo data (scores, ranks, reviewer highlights)
  charts/ → mounted at /charts/ (Plotly HTML)
archetypes/reviews.md        ← template for `hugo new reviews/<slug>.md`
```

**Data split:** editorial fields (title, director, nominator, nomination votes, synopsis)
live in each review's Markdown. Everything numeric (scores, rank, top category, consensus,
The Fan / The Cynic / The Specialist) is computed from `master-data/*.csv` on every build
and joined to the review by `score_key`.

## Data pipeline

| Script | When | What |
|---|---|---|
| `scripts/migrate_wordpress.py` | once (done) | WordPress XML → `content/reviews/*.md` + images. Won't overwrite existing files without `--force`. Writes `master-data/wordpress/migration-report.md`. |
| `scripts/build_data.py` | every build | CSVs + review front matter → `build/data/scores.json` and `build/data/films.json` (the unified master dataset). |
| `scripts/build_charts.py` | every build, after `build_data.py` | CSVs → `build/data/charts.json`: the Plotly charts for `/analytics/` and `/analytics/details/`. Adapted from the original `website_analysis.py` (kept in `scripts/legacy/`). |

Director/year/display title corrections go in `master-data/film_facts.csv` (used by the migration)
or directly in the review's front matter afterwards.

### Adding a new review

1. Add the scores to `master-data/ratings_by_metric.csv`.
2. `hugo new reviews/<slug>.md`, then fill in the front matter. `score_key` must match the
   CSV `movie` name exactly. Set `draft: false`.
3. Put the image at `assets/images/posters/<slug>.jpg` (any size or aspect ratio).

The home page and archive pick it up automatically, sorted by `date`.

### Which charts appear where

Each analytics page lists its charts in front matter (`charts: [...]` in
`content/analytics/_index.md` and `content/analytics/details.md`), by the keys
used in `build_charts.py`. Reorder or remove them there.

## Score submissions (`/submit.html`)

Members pick their initials, the film and the date, and score the eight
categories. Submissions go to [Formspree](https://formspree.io), which emails
them to you. Each email includes `csv_rows`: eight lines already in
`ratings_by_metric.csv` format, so importing is a paste. Fill in the
`list_user` column (the film's nominator), which the form leaves blank.

One-time setup in `hugo.toml` → `[params.submit]`:

1. **Formspree:** create a form, then set `formspree = "https://formspree.io/f/<id>"`.
   In Formspree's settings, restrict submissions to your domain and keep spam
   filtering on.
2. **Password:** run `py scripts/hash_password.py` and paste the output into
   `passwordHash`. Only the hash is stored. Change the password by
   re-running the script.

The password gate keeps casual visitors out; it isn't real security (a static
site can't keep secrets, and the hash is visible in the page source).

With no endpoint set, `hugo server` shows a preview of the email instead
of sending, so the whole flow can be tested locally.

## Local preview

```powershell
.\dev.ps1 -Install   # first time: installs Python packages, builds data + charts, serves
.\dev.ps1            # after that
```

Then open <http://localhost:1313>. Template, CSS, JS and content edits reload
live. After editing a CSV in `master-data/`, stop the server (Ctrl+C) and run
`.\dev.ps1` again so scores and charts are recalculated.

To run the steps yourself: `py scripts/build_data.py`, then
`py scripts/build_charts.py`, then `hugo server`.

If PowerShell refuses to run the script, allow local scripts once with
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. If `hugo` is missing,
install it with `winget install Hugo.Hugo.Extended`.

## Deployment

`.github/workflows/deploy.yml` builds and deploys on every push to `main`.
It also rebuilds on the 1st of each month, so the "last twelve months"
charts stay current. Pull requests are built as a check but not deployed.

One-time setup:

1. Create a GitHub repository and push this folder to its `main` branch.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. **Settings → Pages → Custom domain:** `deadauteursociety.com`, then tick
   *Enforce HTTPS* once the certificate is issued.
4. At your DNS provider, point the domain at GitHub Pages:
   - `A` records for `@`: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `AAAA` records for `@`: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`
   - `CNAME` for `www` → `<your-github-username>.github.io`

   This switches the domain away from WordPress, so do it last.

Old WordPress review URLs (`/midsommar/`, …) redirect to their new
`/reviews/…` pages.
